# task-tracker — заметки для iOS

## Версия SDK

Проект стоит на **Expo SDK 54** и остаётся на нём намеренно: с мая 2026 Expo
не публикует в App Store версии Expo Go для более новых SDK, а Expo Go —
единственный способ запустить приложение на iPhone без платного Apple
Developer.

Читайте документацию ровно этой версии:
https://docs.expo.dev/versions/v54.0.0/

Не обновляйте SDK и не добавляйте модули, которых нет в Expo Go. Проверить
можно так:

```bash
node -e "console.log(Object.keys(require('./node_modules/expo/bundledNativeModules.json')).join('\n'))"
```

Из-за этого в проекте нет и не может быть: `@expo/ui` (компоненты SwiftUI),
фреймворков `Speech`, `Vision`, `PencilKit` и
`VNDocumentCameraViewController` — все они требуют dev-build.

## Главное правило дизайн-системы

**Если элемент есть у системы — берём системный, а не похожий на него.**

Собственный компонент появляется только тогда, когда системного нет вовсе.
Причина не в экономии: системный элемент перекрашивается при «Увеличении
контраста», уплотняется при «Уменьшении прозрачности», растёт вместе с
Dynamic Type, правильно звучит в VoiceOver и меняется с каждой версией
системы сам. Копия ничего этого не знает и стареет с первого дня.

Отсюда следствие для витрины: **системный элемент не рисуется и не заводится
историей в Storybook**. Его место — раздел «Только на устройстве»
(`src/docs/`), где описание и правила применения без картинки.

Действующих исключений два, и оба названы.

**Поле поиска** (`src/components/SearchField.tsx`). Системного нет:
`UISearchBar` живёт внутри `UINavigationBar` вместе с крупным заголовком, а
заголовок в продукте встроенный — он стоит в одну строку с кнопками управления
списком. Собрано из системных частей: символ `magnifyingglass`, обычный
`TextInput`, системная типографика.

**Выпадающее меню** (`src/components/Menu.tsx`). Меню с якорем к кнопке — это
`UIMenu` внутри `UIButton`, и отдать его в JS может только нативный модуль,
которого в Expo Go нет. Доступный `ActionSheetIOS` на iPhone всегда приезжает
от нижнего края, то есть через весь экран от кнопки, которая его вызвала.
Собрано из системных частей: жидкое стекло `Glass`, символы SF, метрики
`UIMenu`. Триггер измеряет себя сам и отдаёт прямоугольник — меню растёт из
ближайшего к нему угла.

Системный `ActionSheetIOS` остался там, где он правилен: на вопросах вроде
«что сделать с заметками внутри удаляемой папки», а не на выборе из списка.

## Продуктовый слой

Три вещи в системе заменены продуктовыми и меняться обратно не должны:

- **подложка** — тёплая (`#FAF8F5` / `#171614`), карточка на ней чистый белый
  и приподнятый тёплый серый;
- **акцент** — один тёплый (`#C93B26` / `#F2603F`) вместо `systemBlue`,
  тратится скупо;
- **форма хрома** — встроенный заголовок в одну строку со стеклянной капсулой
  управления справа (`HeaderCapsule` в `src/components/Button.tsx`), поиск
  первой строкой списка и круг создания справа в ряду панели вкладок
  (`src/components/BottomBar.tsx`), а не панель инструментов.

Ниже кнопку создания опускать нельзя: панель вкладок рисуется нативно и лежит
поверх содержимого экрана, так что нижняя половина круга ушла бы под неё
вместе с половиной цели касания. Поэтому круг накрывает только верхнюю
половину панели.

Живёт это в `productPalette` внутри `src/theme/colors.ts`. Перечисленные там
токены намеренно исключены из `PlatformColor`; все контрастные токены — текст,
разделители, заливки — остались системными.

## Схемы

Светлая и тёмная — не две темы, а одна система с двумя значениями каждого
токена. Выбор схемы уезжает в `Appearance.setColorScheme`, то есть в
системное окно приложения: вместе с нашими экранами схему меняют панель
вкладок, шапки, клавиатура, алерты и стекло.

## Чего в продукте нет по постановке

Аккаунта, входа, онбординга, синхронизации, совместной работы, подписки и
любой отправки данных наружу. Всё хранится на устройстве. Это не «пока не
сделано» — это решение о продукте.

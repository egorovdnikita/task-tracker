# task-tracker — заметки

Мобильное приложение для заметок: список и сетка, блоки текста и чек-листы,
голосовые записи, сканы документов и рисунки, папки, теги, поиск, напоминания и
корзина. **Всё хранится только на устройстве** — аккаунта, синхронизации и
подписки в приложении нет и не предполагается.

Дизайн-система нативная для iOS: там, где элемент есть у платформы, берётся
платформенный, а не похожий на него. Продуктового в ней ровно три вещи —
тёплая подложка вместо чистого белого и чёрного, один тёплый акцент вместо
системного синего и форма плавающего хрома. Светлая и тёмная схемы — два
значения каждого токена, а не две темы. Жидкое стекло iOS 26 — там, где под
слоем действительно что-то едет.

Приложение и витрина компонентов собраны **из одного набора исходников**: компоненты
написаны на примитивах React Native и рендерятся в Storybook через `react-native-web`.

📚 **Storybook:** https://egorovdnikita.github.io/task-tracker/ (деплоится автоматически из `main`)

### Чего в плите 04 нет и почему

Расшифровка речи, распознавание текста на скане, автоматическая рамка по
границам листа и нажим стилуса живут во фреймворках `Speech`, `Vision`,
`VNDocumentCameraViewController` и `PencilKit`. Обёрток для них в Expo Go нет,
а Expo Go — единственный способ запустить приложение на iPhone без платного
Apple Developer.

Вместо расшифровки и распознавания у записи и скана есть подпись, и ею они
находятся поиском. Это меньше, чем в вайрфрейме, но честно: пустая выдача по
голосовой заметке хуже, чем поле, которое человек заполнил сам.

## Что рисует система, а что мы

Собственный компонент появляется только там, где системного нет. Всё остальное
берётся у платформы — не ради экономии, а потому что системный элемент знает про
среду то, чего не знает наш: перекрашивается при «Увеличении контраста»,
уплотняется при «Уменьшении прозрачности», растёт вместе с Dynamic Type,
правильно звучит в VoiceOver и меняется с каждой версией системы сам.

| Берём у системы | Пишем сами |
| --- | --- |
| Панель вкладок, шапки, свайп «назад» | Карточка заметки, список заметок |
| Сегмент-контрол, выбор даты, тумблер | Инсет-группа списка, строка списка |
| Меню действий, алерты, модальные листы | Чип, пустые состояния, сообщение и кнопка отмены |
| SF Symbols | Поле поиска у нижнего края — системного такого нет |
| Жидкое стекло и материалы | Круглая кнопка создания, редактор блоков |
| Локальные уведомления, микрофон, камера | Холст для рисования (PencilKit недоступен), дорожка звука |

Витрина показывает только то, что `react-native-web` рисует честно. Системные
элементы описаны страницами в разделе **«Только на устройстве»** — без картинок:
подделка задаёт неверную мерку и переезжает в макеты.

Отсюда же правило для витрины: **если элемент есть у системы, он не рисуется и
не попадает в Storybook историей**. Сегмент-контрол в первой версии был своим —
он выглядел похоже и был неправильным, и заменён на системный.

Исключение одно и названо: поле поиска у нижнего края. `UISearchBar` живёт в
шапке, а внизу iOS 26 отдаёт только слот вкладки с ролью `search` — вкладку
поиска продукт не держит. Поле собрано из системных частей: капсула стекла,
символ `magnifyingglass`, обычный `TextInput`.

## Запуск на iPhone

Всё, что описано ниже, работает **без Apple Developer и без Xcode** — через
Expo Go.

### 1. Поставить зависимости

```bash
npm install
```

### 2. Поставить Expo Go на iPhone

Из App Store: [Expo Go](https://apps.apple.com/app/expo-go/id982107779). Нужен
iOS 15.1 или новее; жидкое стекло появится на iOS 26.

### 3. Запустить сервер разработки

Если iPhone и компьютер в одной сети Wi-Fi:

```bash
npm start
```

Если телефон в другой сети — на LTE, в гостевом Wi-Fi, за корпоративным
файрволом, — нужен туннель. Он поднимает публичный адрес через ngrok, и
телефон достучится откуда угодно:

```bash
npx expo start --tunnel
```

Туннель медленнее локальной сети: первая сборка занимает минуту-другую.
Если `--tunnel` ругается на отсутствие ngrok, он уже в `devDependencies` —
хватит `npm install`.

### 4. Открыть QR-код

В терминале появится QR. **Сканировать его нужно штатной Камерой iPhone, а не
Expo Go** — сканера внутри Expo Go на iOS нет. Камера покажет баннер «Открыть в
Expo Go», по нему и переходить.

Если QR не считывается, в терминале рядом с ним напечатан адрес вида
`exp://…` — его можно ввести в Expo Go вручную через «Enter URL manually».

### 5. Разрешения

При первом обращении приложение спросит доступ к микрофону (запись голоса),
камере (скан) и уведомлениям (напоминания). Отказ ничего не ломает: экран
объяснит, чего не хватает, и предложит перейти в «Настройки». Все три
разрешения нужны только для плиты 04 и напоминаний — остальное работает без них.

Записи, снимки и заметки лежат в документах приложения на устройстве и никуда
не отправляются.

### Полезное в терминале

| Клавиша | Что делает |
| --- | --- |
| `i` | Открыть в симуляторе iOS (нужен Xcode) |
| `r` | Перезагрузить приложение |
| `j` | Открыть отладчик |
| `?` | Показать все команды |

### Почему SDK 54

Проект намеренно остаётся на **SDK 54**: с мая 2026 Expo не публикует в App
Store версии Expo Go для более новых SDK, и на устройстве работает только 54-я
— см. [changelog Expo](https://expo.dev/changelog/expo-go-and-app-store-may-2026).

Из этого же следует, чего в приложении нет: `@expo/ui` (компоненты SwiftUI),
`Speech`, `Vision` и `PencilKit` требуют dev-build, а dev-build на устройство —
платного Apple Developer.

## Как добавить компонент

1. Проверить, нет ли у системы своего — если есть, брать его.
2. Создать `src/components/MyThing.tsx` на примитивах React Native и токенах из `src/theme`.
3. Рядом положить `MyThing.stories.tsx` со всеми состояниями — если компонент честно
   рендерится в вебе. Если нет, добавить страницу в `src/docs/`.
4. Экспортировать из `src/components/index.ts`.
5. Push в `main` — GitHub Actions пересоберёт Storybook и обновит GitHub Pages.
